# Mapped World footprints v1

Status: a reproducible modeling and repair experiment, not a novelty,
optimality or general scalability claim. The shared native FPC/pas2js
[workbench](../../examples/passes/07_MappedWorld/README.md), fixtures and this
record are project-authored under the repository's [MIT license](../../LICENSE).
The experiment uses `WFC_PASS_MAPPING_VERSION = 1` and
`MAPPED_WORLD_MODEL_VERSION = 1`; existing solver and portable pipeline
versions are unchanged.

## Question and counterexample

Can a building on a coarse grid require every fine-grid foliage cell it
occupies to be clear, and can an explicitly authorized upstream repair make
a required building possible without rewriting unrelated terrain?

The comparison is between two declared models: a house that reads one foliage
point and a house that reads its whole footprint. A clear corner with an
interior tree is a counterexample to the inference that point-model success
implies physical clearance. It is not a failure to solve the point model.
Because these models admit different assignments, their search costs would
not be an equivalent-model solver benchmark.

## Coordinates and predicates

All three bounded grids occupy integer world coordinates. Their topology is
fixed in this showcase, not an upper limit imposed by the mapped-pass API.

| Pass index / layer | Cells XYZ | World origin | Cell pitch |
| --- | --- | --- | --- |
| 0 / terrain | 8 × 6 × 1 | 0,0,0 | 4,4,1 |
| 1 / foliage | 32 × 24 × 1 | 0,0,0 | 1,1,1 |
| 2 / housing | 3 × 2 × 1 | 4,4,0 | 8,8,1 |

A cell at index `i` occupies the half-open box
`[origin + i*pitch, origin + (i+1)*pitch)`, component by component.
Provider box `P` intersects query box `Q` exactly when
`P.min < Q.max` and `Q.min < P.max` on every axis. Merely touching an edge,
face or corner is not intersection. Point membership includes the lower
boundary and excludes the upper boundary. Bounded queries must lie entirely
inside the provider world; they are not clipped to a convenient subset.

The selected model requires:

- A tree's lower world point is on land. Clear foliage is allowed on land or
  water. Here the fine cell lies entirely inside its containing terrain cell.
- Every terrain cell intersecting a house footprint is land.
- Every foliage cell selected by the configured house query is clear.
- Each entry respects its caller lock, effective domain and housing demand.

Cell sampling uses the complete house box. Point study samples only its lower
corner. Region sampling uses a relative half-open XYZ box in world units;
`0,0,0:8,8,1` equals the house footprint, while `-1,-1,0:9,9,1` adds a one-unit
setback. These study choices change the foliage query, not the full terrain
requirement. The independent physical policy always checks the entire house
footprint for land and clear foliage, regardless of selected sampling.

Housing site `(0,0)` occupies `[4,12) × [4,12) × [0,1)`. It intersects four
terrain cells, `(1,1)`, `(2,1)`, `(1,2)`, `(2,2)`, and 64 foliage cells whose
X and Y indices run from 4 through 11. A tree at `(7,7)` intersects that box
but does not occupy the point `(4,4,0)`.

## Complete tutorial fixture

The `interior` preset discloses its zoning rather than presenting it as an
unrestricted landscape:

- All 48 terrain cells have the domain `{land}`.
- 767 foliage cells have the domain `{clear}`. Only `(7,7)` has no preset
  restriction, so it can be tree or clear.
- All six housing sites initially demand vacant. There are no caller locks.
- Palette order is terrain `land, water`; foliage `tree, clear`; housing
  `house, vacant`. Study weights are all one. Seed is `3`.
- Search uses 64 local backtracks per pass and 16 pass backtracks, with no
  implicit restart, wider repair scope or search for a favorable seed.

The baseline is actually generated by WFC: `(7,7)` becomes a generated tree,
`(4,4)` is clear and every house is vacant. The host never writes a synthetic
generated value. Only after that baseline exists does the experiment require
house `(0,0)`, retaining every other demand and domain.

The separate `sandbox` preset leaves terrain and foliage domains unrestricted
and houses optional, with editable land/water and clear/tree weights initially
12/1 each. Both presets expose domain overrides, explicit caller locks and
housing demands. Clearing a user domain override restores preset zoning;
it does not erase a house demand. Requiring a house must not silently fall
back to vacant. The sandbox is broader than this deliberately small fixture,
and is not promised the same easy repair.

## Observed outcomes

Each row starts from its corresponding generated seed-3 baseline and then
requires house `(0,0)`. Pass indices below are the actual authorized closure.

| Foliage query / search | Active passes | Outcome |
| --- | --- | --- |
| Point / negotiated housing repair | `[2]` | Selected model satisfied; interior tree remains. Independent physical policy fails. Safe SVG is refused; an explicit unsafe diagnostic is available. |
| Cell / ordinary housing repair | `[2]` | Contradiction. The tree is outside repair authority. No current output is published. |
| Cell / negotiated housing repair | `[2]` | Still fails. Negotiated mode does not grant authority over foliage. |
| Cell / negotiated foliage repair | `[1,2]` | Solved after one excluded provider assignment and two rounds. WFC generates clear at `(7,7)`, the required house is physically safe, and terrain is preserved. |
| Cell / negotiated foliage repair, zero pass budget | `[1,2]` | Pass limit, not proof of impossibility. A later explicitly requested run with budget 16 succeeds. |

The successful tutorial repair excludes the complete foliage assignment, not
an independently inferred minimum blocker set. Its narrow zoning makes that
whole-assignment exclusion useful. With hundreds of free cells, subsequent
assignments may change irrelevant cells instead of the blocker; the same
chronological coordinator can exhaust its budget without finding a repair.

## Reproduce

Use the [isolated checked native build](../../examples/passes/07_MappedWorld/README.md#native-build-and-walkthrough)
or the [repository build](../building.md#mapped-world-browser-and-native-hosts).
Run the resulting `MappedWorld` executable with the following arguments; the
defaults omitted here are the exact fixture settings above. Output files must
not already exist.

```text
MappedWorld --selftest
MappedWorld --preset interior --seed 3 --inspect 0,0
MappedWorld --seed 3 --ordinary --demand 0,0=house --repair housing
MappedWorld --seed 3 --demand 0,0=house --repair housing
MappedWorld --seed 3 --demand 0,0=house --repair foliage --trace --svg repaired.svg
MappedWorld --seed 3 --sampling point --demand 0,0=house --repair housing --diagnostic-svg point-study.svg
MappedWorld --seed 3 --demand 0,0=house --repair foliage --pass-backtracks 0
```

Each edited CLI invocation generates its initial baseline before applying
edits, then performs exactly the requested repair; it does not first solve an
easier final demand. Expected contradiction/limit runs exit 2, and the unsafe
point study exits 3 even if its explicitly diagnostic export succeeds. A safe
successful run exits 0. See the demo guide for the complete exit contract.

For the browser, stage `build-browser-mapped.ps1` or
`bash ./build-browser-mapped.sh`, then use the included native FPC server to
serve `build/browser/mapped/www`. Select the interior preset, seed 3 and cell
sampling; start a new session and Generate before setting the house demand.
Try housing-only and then explicit foliage repair. A new point-study session
provides the counterexample. `?selftest=1` runs the actual entry fixture.
The [development tools](../development-tools.md) run portable tests through
the project-owned FPC server, browser capture and checker. Compilation alone
is not browser execution evidence.

## Validation, identity and publication

The [independent validator](../../examples/passes/07_MappedWorld/mapped_world_validation.pas)
enumerates literal provider boxes. It does not call the solver or its lattice
coverage iterator as an oracle. It recomputes selected-model validity and
full-footprint physical safety from detached values, layouts, domains, locks
and demands, ignoring saved validity flags. Model validation runs inside the
graph's commit transaction; a failed candidate is rejected before publication.

Edits immediately hide current output. A normal failed repair retains only
the previous committed baseline for later authorized repair and clearly
labeled inspection. It is not represented as satisfying the new edits.
Safe SVG requires a current result, both independent validity checks and its
matching signature. Explicit diagnostic SVG labels unsafe studies and retained
`NOT CURRENT` snapshots. Selecting an inspection site does not edit the model.
The native and browser hosts use the same Pascal SVG implementation.

Reports retain requested roots, actual closure, options, failures, per-pass
and aggregate search counters, trace identity and negotiation history. A
selective transcript signature binds the scope version, requested roots and
active closure as well as the inner search transcript; the inner chronology
hash remains separately available. Published results pin that scope-bound
signature. These deterministic identities detect regressions; they are neither
semantic validators nor cryptographic provenance.

## Focused evidence and limits

Focused executions observed on 2026-09-06:

| Executable fixture | Checked native, each of four targets | Actual pas2js / Edge browser |
| --- | --- | --- |
| [Mapped core](../../test/wfc_mapped_passes_test.lpr) | 938 / 938 | 1188 / 1188 |
| [Shared session owner](../../test/wfc_mapped_world_test.lpr) | 75 / 75 | 87 / 87 |
| [Independent geometry, inspection and SVG](../../test/wfc_mapped_world_geometry_test.lpr) | 859 / 859 | 899 / 899 |

Native targets were FPC 3.2.2 and development FPC 3.3.1, each on Windows 32-bit
and 64-bit, rebuilt with `-B -Mdelphi -Sa -Cr -Co -Ci`. Browser execution used
pas2js 3.3.1 and the included FPC host/capture/checker, not a second solver
implementation. Browser-only hostile-input and interop assertions account for
different check totals. The owner suite covers the real generated blocker,
both leaf failures, authorized repair, scope-bound signature recomputation,
detached copies, lock/unlock, empty domains, dirty-provider scope rejection,
atomic invalid reset, sandbox generation, region/setback checks and refusal to
export unsafe or stale output as safe.

The actual Mapped World browser entry also passed its 16-assertion fixture,
including rejected-edit isolation, queued-operation cancellation and recovery,
and inactive-preset input handling. The native CLI process suite passed
76 cases / 116 checks on each of the four native targets.

The full maintained native build passed on stable FPC 3.2.2 Win32, including
all registered tests, tools and example smoke checks. Its private verification
wrapper retained exit 1 solely because its final worktree audit detected one
terminal newline removed from the native process test after the snapshot was
frozen; the build itself returned zero and all 605 snapshot files were unchanged.
No executable test statement differed.

The full browser run built 139 portable programs and passed 138 on its first
execution, including all 11 actual demo entries. The existing Ensemble
development case exhausted its unchanged 60-second capture deadline without
a captured assertion result. One separately labeled re-execution, after both
full builds had finished, passed all 2,361 checks using byte-identical compiled
assets and the same deadline. That does not turn the first run into a complete
pass or establish the cause of its timeout. Near-deadline capture remains a
timing-sensitivity risk. Desktop/mobile visual review remains unverified;
functional browser tests are not visual approval. Earlier complete-repository
runs remain evidence for their recorded revisions.

The workbench does not resize its grids, stream an unbounded world, provide
minimal-edit/conflict-directed negotiation or guarantee repair within a budget.
Current portable recipe/run/result formats cannot save and reconstruct these
unlike layouts and mapped clauses; that needs a versioned extension. SVG is a
presentation artifact, not a saved executable model. Broader topologies,
portable mapped persistence and more targeted provider exclusions are follow-up work. Nothing
here proves aesthetic quality, performance on general free landscapes or
priority over existing literature.
